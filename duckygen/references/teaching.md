# Explain through visible cause and effect

Use for educational films, science questions and requests such as “explain this” within a Duckygen video task. Answer the actual question in plain language, then make the animation demonstrate why. If the user asks only for text, a calculation or a still diagram, honor that scope. An explanation request during an existing edit is not permission to replace the project.

## Build the explanation before the spectacle

Identify the learner, the exact question, the likely misconception and the minimum prerequisite. Default to an interested beginner when no audience is given. Choose a familiar example; introduce unfamiliar terms when their object first appears. Give a useful short answer early, with qualifications where they matter. Do not turn a straightforward answer into a long mystery or require a quiz before helping.

A useful arc is question → prediction or contrast → visible mechanism → rule/equation → worked example → return to the question. Adapt it to the topic. For each major narrated claim, specify what the viewer will see change and what that change proves. Put this in the existing shot plan, not a second competing timeline. A title changing over a stationary drawing does not demonstrate a mechanism.

Show the concrete thing first. Name it. Highlight the relevant part. Change one important variable. Show the outcome and explain the causal link. For a comparison, keep all other conditions, scales and clocks consistent. Give a difficult step time to become readable, then reveal the next relationship. Voice, focus cues, measurements and captions use the same measured scene times.

Keep a recurring object or system across shots so the viewer can follow it. Use wide context, close inspection, a state change, a comparison, and a worked example where they advance understanding. Reframe at a new question or causal event; do not fragment the physical action just to meet a cut count. The learner should be able to point to the cause without rereading a paragraph.

## Equations explain the scene

Introduce each symbol beside its visible object and give its units. Explain the relationship in words before manipulating notation. Keep the equation on screen while the corresponding state changes. Distinguish vectors, magnitudes and signed components. Show substitution with units, compute the result, then compare the predicted result with the animation. Do not display unexplained algebra as a decorative background or animate an answer before calculating it.

Use proportional quantities honestly: force-arrow length for force, distance for position, slope for velocity, area under a curve for an integral. If an arrow is only directional, say so. Attach labels and arrows to transformed object anchors. Do not let an arrow imply force when it represents velocity or information flow.

For questions without enough numerical data, give the symbolic answer or a clearly labeled example with stated assumptions. If the premise is false, show the correcting comparison. If a general mechanism is uncertain or outside a simple model, say what the illustration can establish and what needs a more specific model or source.

## Review comprehension

Inspect the key sequence without captions: is the cause visible? Then inspect with narration/captions: does the named event occur at the spoken moment? Check whether the final result answers the opening question, whether beginners can identify each object, and whether counterexamples or limiting conditions change the conclusion. Use a brief transfer example when it adds learning; quizzes and character stories are optional.
